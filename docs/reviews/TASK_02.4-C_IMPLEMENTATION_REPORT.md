## Implemented and architecture

- Authorization-code popup flow with PKCE S256, nonce and signed, HttpOnly, five-minute browser transaction state.
- Official Google Auth Library verifies the ID token cryptographically, including audience, issuer and expiration; the backend additionally validates subject, verified email and nonce.
- OAuthAccount is the canonical identity, keyed by provider and subject. New customer/identity creation is atomic and uniqueness races resolve to the winning identity.
- Existing customer sessions, refresh rotation, cookies, access JWT, AuthContext and shared password controls are reused. Password login, verification and Google sign-in share the existing session creation helper.
- Email equality never links automatically. Existing account linking requires the verified Google transaction, the exact frontend Origin and a valid existing password on an active, verified CUSTOMER. Identities cannot be reassigned. GOOGLE_CONNECTED and LOGIN_SUCCESS events are persisted.
- Provider codes/tokens are not persisted. OAuth query strings are excluded from application logs. Popup messages contain status only and validate opener source and origin.

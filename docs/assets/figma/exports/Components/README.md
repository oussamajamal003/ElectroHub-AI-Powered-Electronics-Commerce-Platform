# Admin Screenshots — Figma Make Visual References

## Purpose

This folder contains screenshots captured from the **ElectroHub Figma Make** design workspace for the **Admin Experience**.

The screenshots are visual references for implementation and visual QA. They document how the admin dashboard, management screens, forms, tables, navigation, and responsive states were presented in Figma Make.

**Figma Design remains the authoritative visual source of truth.** These screenshots must not be treated as a replacement for the live Figma Design file.

---

## Source

### Figma Design

The live **Figma Design** file is the authoritative source for:

- Layout and visual structure
- Components and variants
- Design tokens
- Typography
- Colors
- Spacing
- Responsive behavior
- Interaction and state definitions

When a screenshot and the live Figma Design appear to conflict, inspect the live Design source before making an implementation decision.

### Figma Make

Figma Make is used here as a **visual reference source**.

Screenshots may be used to understand:

- The intended appearance of admin screens
- Composition of complete screens
- Page-level visual hierarchy
- Responsive presentation
- States and UI examples that are useful during implementation

The screenshots are not the implementation source and should not be used to infer undocumented behavior when the Design source provides the answer.

---

## Screenshot Policy

### Keep Figma Make's Default Filenames

Screenshots exported or captured from Figma Make should retain the **default filename generated by Figma Make**.

Do **not** manually rename screenshots to a custom convention such as:

```text
Admin Dashboard — Desktop.png
Products — Desktop.png
Orders — Mobile.png
```

Also do not introduce a mandatory:

```text
<Screen> — Desktop.png
<Screen> — Tablet.png
<Screen> — Mobile.png
```

naming pattern.

The filename itself does not need to encode the screen, state, or viewport.

Context should instead be provided by:

- This README
- The folder location
- The screenshot's visible Figma Make content
- The corresponding Figma Design screen/frame

Do not rename, normalize, or invent filenames unless an explicit repository requirement is introduced later.

## Important Admin Responsive Decisions

The following decisions were established during the final design work and should be preserved when reviewing these screenshots:

- The **Admin Sidebar** has a collapse control at the top of the sidebar.
- The sidebar remains sticky beneath the header.
- The main content area scrolls independently as appropriate.
- The main content resizes when the sidebar is collapsed.
- Dashboard **Sales Overview** must remain usable responsively.
- **Orders by Status** must stack appropriately on smaller screens.
- Admin forms must remain usable on smaller viewports.
- Data-heavy interfaces must avoid creating unusable horizontal layouts.
- Mobile layouts should prioritize readable content and accessible controls.

## Accessibility

Admin screenshot review should verify that the implementation preserves the accessibility intent established by the design system.

Pay particular attention to:

- Visible keyboard focus
- Sufficient text/control contrast
- Accessible icon buttons
- Form labels
- Validation messaging
- Disabled-state clarity
- Keyboard-friendly dialogs and menus
- Escape behavior for dismissible overlays
- Usable controls at smaller viewports
- Clear status communication that is not dependent on color alone

The established focus treatment uses a **2px primary-blue focus ring with a 2px offset**.

## Source and Evidence Rules

### Do

- Use the live Figma Design for authoritative visual decisions.
- Use Figma Make screenshots as supporting visual references.
- Inspect the corresponding Design frame when precision is required.
- Reuse existing design tokens and components.
- Preserve established responsive behavior.

- Treat screenshots as the source of truth over the live Design file.
- Redesign the admin experience because of implementation convenience.
- Invent undocumented colors, spacing, typography, or interactions.
- Rename screenshots to create a custom naming system.
- Treat screenshot filenames as semantic identifiers.
- Extract or reconstruct Figma Make source code from screenshots.
- Create repository screenshots for the Figma Design source unless explicitly required.
